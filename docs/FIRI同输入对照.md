# Hermite 与仓库内 FIRI 的同输入对照

后续已解除 1.5 m 限制，并将生成阶段的扩张范围统一为 3 m 局部盒，见[同范围扩张复测](FIRI同范围扩张对照.md)。本文保留上一轮配置和结果。

日期：2026-11-02。对照基线为提交 `d7b9cbc` 中的 Hermite 模块，以及本仓库 `gcopter/include/gcopter/firi.hpp` 的 FIRI 实现。这里只测试三条预先保存的代表路径，没有重新搜索种子，也没有扩展到整批 26 条。

**在这三条路径和当前参数下，FIRI 的几何并集更大，生成耗时更低。当前 Hermite 的主要能力是直接输出 C² 可微截面，不应宣称它已在体积或速度上超过 FIRI。**

## 当前实体障碍安全配置

两侧使用相同地图、种子折线、世界边界、0.25 m 体素、0.2 m 机器人半径、0.05 m 安全距离及 0.002 m 额外认证余量。Hermite 每节点最大半轴 1.5 m、最大中心偏移 1.5 m、间距 0.4 m。FIRI 沿用 4 次迭代、`progress=7 m`、名义局部 `range=3 m` 和 `shortCut`。

FIRI 原实现只接收点障碍，因此本表使用 **FIRI 生成 + 同安全距离收缩**，不是声称原实现直接支持球体障碍。方法及原始点模型对照在下文。

| 保存路径 | Hermite 并集体积 | FIRI 安全收缩后并集体积 | Hermite 生成 | FIRI 生成、收缩及 shortCut |
|---|---:|---:|---:|---:|
| RViz 交互路径 1 | 233.4 ± 0.5 m³ | 519.9 ± 0.6 m³ | 60.9 ms | 26.4 ms |
| Perlin，23 次明显转弯 | 346.7 ± 0.9 m³ | 586.9 ± 0.7 m³ | 138.3 ms | 49.0 ms |
| 迷宫路径 | 260.3 ± 0.3 m³ | 542.5 ± 0.3 m³ | 82.5 ms | 29.4 ms |

三例中 FIRI 的体积为 Hermite 的 **1.69–2.23 倍**，生成速度约为其 **2.31–2.82 倍**。所有 FIRI 输出均非空、首末端点在走廊内、相邻保留多面体有体积重叠，并通过实体球体分离和地图边界检查。

为排除 FIRI 局部盒子角落及端部扩张带来的部分影响，另将两者都裁到“距原始种子折线不超过 3 m”的公共评估范围：

| 路径 | Hermite 公共范围内体积 | FIRI 公共范围内体积 |
|---|---:|---:|
| 交互路径 | 233.4 m³ | 467.7 m³ |
| 23 转弯路径 | 346.7 m³ | 544.9 m³ |
| 迷宫路径 | 260.3 m³ | 519.3 m³ |

裁剪只用于评估，不参与生成。此时 FIRI 体积仍为 Hermite 的约 **1.57–2.00 倍**。三例中采样未发现 Hermite 有落在该公共范围外的体积。

## 原始点障碍模型对照

为单独观察原算法的差异，再令两侧都使用零半径障碍点、零机器人半径和零用户安全距离。Hermite 仅保留 1e-8 m 数值认证余量。FIRI 使用原始地图边界和 `range=3 m`，没有安全收缩。

| 路径 | Hermite 并集体积 | FIRI 原算法并集体积 | Hermite 生成 | FIRI 生成及 shortCut |
|---|---:|---:|---:|---:|
| 交互路径 | 287.8 ± 0.7 m³ | 762.1 ± 0.5 m³ | 44.1 ms | 22.4 ms |
| 23 转弯路径 | 470.7 ± 1.0 m³ | 893.4 ± 1.3 m³ | 114.2 ms | 42.4 ms |
| 迷宫路径 | 326.1 ± 0.7 m³ | 792.3 ± 0.5 m³ | 54.7 ms | 23.8 ms |

该表是相同点模型下的算法输出比较，**不能当成实体体素/机器人的安全结果**。三例中 FIRI 仍连通，体积和生成速度的优势方向一致。

## 体积和计时口径

- 表中体积是空间集合的**并集体积**，不是多个多面体体积之和，也不是截面面积简单乘以路径长度。重叠区域只计一次。
- Hermite 点归属通过每段的截面平面多项式求根及椭圆内外测试实现。平面方程最高 15 次，以 Bernstein 符号变化和细分分离根；不只求一个最近截面。多根、折返扫掠和重复曲面片都有独立回归测试。
- FIRI 用半空间不等式检查归属。包围盒使用独立的三平面交点枚举求得，顶点须通过全部半空间检查；不依赖 FIRI 的 H→V 转换来决定网格分配尺寸。
- 体积采用 8 组独立数字移位的 Sobol 点，每组 65,536 点，共 524,288 点/模型/路径，边生成边统计。表中 ± 是根据这 8 组估计得到的近似 95% 误差半宽，不是形式化上下界。
- 生成耗时先预热一次，再取三次测量的中位数。每轮交替先运行 Hermite 或 FIRI。FIRI 时间包含全点云筛选、四轮区域生成、可选安全收缩和 `shortCut`；Hermite 包含其内部连续证书及优化。
- 两侧均不计文件读取、路径搜索、体积统计、独立验证或显示时间。Hermite 的可复用 BVH 建立时间另列在 JSON 的 `index_ms`，不计入表格；FIRI 原包装器的全点云筛选仍计入生成时间。对单次冷启动，Hermite 还要增加建索引的成本。
- 同一台 Ryzen 7 9700X、Release 构建；仅串行运行，不开 RViz，不并行跑样本。三次测量和三条路径不足以代表所有场景或实时最坏耗时。

## FIRI 的实体安全适配

FIRI 核心文件未修改。基准包装器沿用 `sfc_gen::convexCover` 的段划分、点云筛选、补间区域逻辑，只修补空点集访问并检查返回值。

令体素外接球半径为 `r_v = sqrt(3)*0.25/2`，总收缩距离为：

```
rho = r_v + 0.2 + 0.05 + 0.002
```

先在点中心地图上运行 FIRI，再将每个归一化平面 `n·x+d <= 0` 改为 `n·x+d+rho <= 0`，最后执行 `shortCut`。为避免额外缩小人工局部盒子，生成时局部 range 使用 `3+rho`；世界边界向外扩 `r_v`，使收缩后的世界边界与 Hermite 的机器人净空边界一致。

一个点被原半空间分离后，收缩平面也能分离以该点为中心、半径 rho 的球。基准仍独立核验全部相关球体和边界，并检查收缩后的连通性。一般情况下，后收缩可能损失连通性；本次三条路径均通过，不能据此保证其他路径都通过。这是一个明确的安全适配层，不是原 GCOPTER 的体素膨胀管线。

## 如何解释差距

本次比较对齐了输入与安全距离，没有把两种表示强行改成相同的可行集合：

- Hermite 的实际输出限制为椭圆截面，节点半轴上限 1.5 m。即使空间允许，更高、更宽的截面也会受此上限限制。
- FIRI 输出完整凸多面体，能利用椭圆截面没有覆盖的角落，也没有同样的椭圆半轴上限。公共 3 m 评估范围只能消除部分空间范围差异。
- 当前 Hermite 还要联合优化大量截面变量并保证 C² 拼接、连续安全和非退化；FIRI 生成的分段多面体边界本身不连续可微。

因此，结果支持“这三条路径下，当前 FIRI 管线得到更大区域并且生成更快”，不能直接解释为样条凸包造成了同等比例的额外保守，也不能推导任意参数下两者的优劣。

## 内存修复与轻量复现

初次体积统计程序触发过 OOM，内核记录约 23 GiB 匿名内存。初始结果已作废，未纳入本文。问题出在新增计量工具的防护不足：未经核验的 H→V 包围盒直接决定网格分配规模。现在已替换该转换、显式物化 Eigen 网格边界，增加 50,000 网格和 2,000,000 个候选关联上限，并在分配前检查异常尺寸。

运行脚本强制单进程串行，每个基准进程限制 **512 MiB 虚拟内存、30 秒 CPU 时间**，超时终止整个进程组。最终六次运行的 RSS 峰值为 **24.6–30.1 MiB**。体积采样数量只增加运行时间，不批量分配采样点数组。

基准目标默认不参与普通构建。已构建的当前工作区可直接运行：

```bash
python3 gcopter/tools/run_firi_comparison.py \
  --input .scratch/interactive/rviz/run_1793605002598226995_3712673/request_1 \
  --input .scratch/interactive/perlin_final/run_1793605176741410828_3715435/request_10 \
  --input .scratch/interactive/maze_connected/run_1793605479006343675_3719882/request_10 \
  --output .scratch/firi_comparison_replay --repeats 3 --samples 65536
```

若需重新编译，先加载本机 ROS/install 环境，配置 `-DGCOPTER_BUILD_CORRIDOR_BENCHMARK=ON`，然后只构建两个目标，限制为单任务：

```bash
prlimit --as=2147483648 --cpu=90 cmake --build build/gcopter \
  --target corridor_firi_benchmark corridor_volume_test -j1
prlimit --as=536870912 --cpu=15 build/gcopter/corridor_volume_test
```

体积测试覆盖解析圆柱体积、重叠立方体并集、重复曲面片、平面方程多根、折返扫掠的去重，以及超大网格分配前拒绝。
