# C3 原生走廊的 RViz2 交互测试

演示默认使用最新 `当前默认算法`：原 mockamap 地图、原 Informed RRT*
搜索、原生 C3 生成和连续认证。点选起终点后只生成走廊，不运行轨迹优化。

```bash
cd /home/zdp/ForCodex/GCOPTER
./gcopter/tools/run_direct_demo.sh scene:=perlin shape_mode:=c3 search_timeout:=1.0
```

迷宫场景：

```bash
/home/zdp/ForCodex/GCOPTER/gcopter/tools/run_direct_demo.sh \
  scene:=maze shape_mode:=c3 search_timeout:=3.0
```

等待地图出现，连续两次使用工具栏 **2D Goal Pose**，依次选择起点、终点。
默认高度为 2.5 m，可通过 `height:=2.0` 调整。完成后再次点选可开始新路径；
**2D Pose Estimate** 或面板“重新选点”可重置选择。

红色半透明曲面为走廊，深红线为走廊中心，橙色线为搜索路径。
左侧面板显示走廊生成时间、搜索时间、路径长度和最小半轴。障碍物透明度可在
面板调整。`/direct_demo/metrics` 发布 JSON，搜索、生成、绘制导出时间分别记录。

默认输出目录 `/tmp/gcopter_direct_demo/run_*/request_*` 保存种子路径、中心线、
系数和 `metrics.json`。`cubic_controls.csv` 为真实三次 v3 系数（每段四行）；
显示层精确升阶后复用已有绘制器，`controls.csv` 与 `~/controls` 为等价的六行
五次 Bézier 显示数据，标签仍标记为 v2。升阶没有拟合或改动几何，其时间在
`visualization_adapter_ms` 中单独统计，不计入 `corridor_ms`。

可用 `shape_mode:=smooth` 运行 H5 对照。重新搜索会改变路径，不应把不同点击
请求当作同输入性能 Benchmark。关闭窗口或终端按 Ctrl+C 停止本次演示。

本机重新构建：

```bash
cd /home/zdp/ForCodex/GCOPTER
bash -c 'source /opt/ros/lyrical/setup.bash
export MAKEFLAGS="-j1 -l1" CMAKE_BUILD_PARALLEL_LEVEL=1
colcon build --packages-up-to gcopter mockamap --executor sequential --parallel-workers 1 \
  --cmake-args -DDIRECT_CORRIDOR_BUILD_ROS2=ON -DCMAKE_BUILD_TYPE=Release'
```

## 本机验证

串行构建三个 ROS 包通过。集成测试向与 RViz2 相同的目标话题发送起终点，
使用原 Perlin、迷宫地图重新搜索，均返回 `PASS`、`native_cubic_v3` 和非空曲面。
本次生成耗时分别为 27.90 ms、34.33 ms；这是两次交互链路烟雾测试，不是
冻结路径的重复性能比较。测试未运行轨迹优化，结束后关闭其启动的节点。

记录：[Perlin](validation/c3_rviz/perlin_smoke.json)、
[迷宫](validation/c3_rviz/maze_smoke.json)。复跑消息链路测试：

```bash
cd /home/zdp/ForCodex/GCOPTER
bash -c 'source /opt/ros/lyrical/setup.bash; source install/setup.bash
ROS_DOMAIN_ID=187 python3 gcopter/tests/c3_demo_smoke.py'
```

另完成 RViz2 启动检查：窗口进程和 OpenGL 4.6 初始化正常，没有插件加载错误；
启动检查后关闭测试进程。日志见 [RViz2 启动记录](validation/c3_rviz/rviz_startup.log)。
