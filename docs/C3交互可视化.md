# C3 原生走廊的 RViz2 交互测试

演示默认使用当前默认的 C3 算法：原 mockamap 地图、原 Informed RRT*
搜索、原生 C3 生成和连续认证。点选起终点后只生成走廊，不运行轨迹优化。

```bash
cd /home/zdp/ForCodex/GCOPTER
./gcopter/tools/run_direct_demo.sh scene:=perlin search_timeout:=1.0
```

迷宫场景：

```bash
/home/zdp/ForCodex/GCOPTER/gcopter/tools/run_direct_demo.sh \
  scene:=maze search_timeout:=3.0
```

等待地图出现，连续两次使用工具栏 **2D Goal Pose**，依次选择起点、终点。
默认高度为 2.5 m，可通过 `height:=2.0` 调整。完成后再次点选可开始新路径；
**2D Pose Estimate** 或面板“重新选点”可重置选择。

红色半透明曲面为走廊，深红线为走廊中心，橙色线为搜索路径。
左侧面板显示走廊生成时间、搜索时间、路径长度和最小半轴。障碍物透明度可在
面板调整。`/direct_demo/metrics` 发布 JSON，搜索、生成、绘制导出时间分别记录。

默认输出目录 `/tmp/gcopter_direct_demo/run_*/request_*` 保存种子路径、中心线、
系数和 `metrics.json`。`cubic_controls.csv` 为真实三次 v3 系数（每段四行）；
显示层直接使用 `SweepCorridor::Corridor` 的查询接口。`controls.csv` 与
`~/controls` 均按三次输出，每段四行，消息 layout 标记为
`cubic_bezier_controls_v3`。

当前分支只保留 C3，不再提供 `shape_mode` 开关。H5 完整代码与对照结果保存在
`archive/h5-sweep-corridor` 分支（`bd6d81f`）。重新搜索会改变路径，不应把不同点击
请求当作同输入性能 Benchmark。关闭窗口或终端按 Ctrl+C 停止本次演示。

本机重新构建：

```bash
cd /home/zdp/ForCodex/GCOPTER
bash -c 'source /opt/ros/lyrical/setup.bash
export MAKEFLAGS="-j1 -l1" CMAKE_BUILD_PARALLEL_LEVEL=1
colcon build --packages-up-to gcopter mockamap --executor sequential --parallel-workers 1 \
  --cmake-args -DDIRECT_CORRIDOR_BUILD_ROS2=ON -DCMAKE_BUILD_TYPE=Release'
```

## C3 专用版本验证

Perlin 和迷宫的 RViz 目标消息链路均返回 `PASS`、`native_cubic_v3` 和非空曲面。
本轮单次生成耗时分别为 23.91 ms、33.97 ms；这是交互烟雾测试，不是冻结输入性能排名。
测试未启动 RViz 窗口，也未进行轨迹优化，结束后关闭其启动的节点。
