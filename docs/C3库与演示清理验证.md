# C3 库与演示清理验证

本轮以 `62645e2` 为基线，收敛库接口、构建依赖和实验工具，不修改优化目标、连续证书、安全余量或迭代预算。

## 结构调整

- 删除未调用的 `generateNative()`、`Geometry::append()`；几何段读取固定为三次，通用 Bernstein 证书工具继续保留。
- 删除 `CubicOptions` 继承层，内部直接使用几何选项。内外共用一套 `Status`，生成结果以枚举传递，不再经过字符串反查。
- 删除 `direct_corridor` 转发头文件、独立 CMake/ROS 包和地图/路径订阅节点。GCOPTER 与轨迹实验直接链接 `SweepCorridor::SweepCorridor`。
- CLI、合成案例 benchmark、回放和示例迁入 `SweepCorridor/benchmarks`，通过默认关闭的构建选项启用，不随消费库强制构建。
- 轨迹实验只编译一个 `trajectory_comparison`，默认比较 C3/FIRI；`SWEEP_C3_ONLY=1` 用于 C3 回放，比较脚本自动设置。五次最小 jerk 轨迹及独立反求参考实现继续保留。
- 保留原地图、搜索、RViz2 起终点点选、面板及曲面可视化。

几何与支撑平面完全一致，因此扫掠体积、边界平滑性和连续安全模型保持不变，本轮无需用采样体积重新估计同一几何。失败案例也纳入统计。

## 构建迁移说明

旧工作区缓存的 `SweepCorridor_DIR` 可能仍指向原 `install/gcopter_direct_corridor`。首次迁移应清除 CMake 缓存，或显式指定新安装目录。旧转发包的本地 build/install 已移出工作区安装树。

ROS 首次重建发现 colcon 仍向 Make 传入 `-j16`，并且沿用了旧安装路径；该次构建已中止，不计入验证。最终改用显式新库路径、`cmake --build -j1` 重建。文档命令增加 `MAKEFLAGS=-j1`（只设包级 sequential 或 CMAKE_BUILD_PARALLEL_LEVEL 不能约束此版本 colcon 的 Make 并行参数）。同输入性能回放此前独立串行完成，不受这次构建影响。
