# 解除 1.5 m 限制后的同范围 FIRI 对照

此处保留提交 `661dd28` 的基线结果；后续约束与求解器改进见[体积与速度优化](Hermite体积与速度优化.md)。

日期：2026-11-02。在上一轮相同的三组保存地图和种子路径上复测，统一使用 FIRI 的 `progress=7 m`、名义 `range=3 m` 局部扩张盒。全程串行，基准子进程限制 512 MiB 虚拟内存。

**实体安全模型下，Hermite 并集体积比原配置增加 40.1%–52.0%，达到 FIRI 的 67.2%–83.1%；生成耗时增加到 120.6–238.1 ms，约为 FIRI 的 4.1–4.8 倍。** 这是三条路径的实测结果，不代表所有环境。

## 统一扩张范围的实现

沿种子折线划分线段，长边以 7 m 为步长切分。每段端点为 `a,b`，允许区域为：

```text
lower = max(min(a,b) - (3,3,3), world_lower + clearance)
upper = min(max(a,b) + (3,3,3), world_upper - clearance)
clearance = robot_radius + safety_margin + certificate_margin
```

这是沿世界坐标轴扩张的盒子，允许斜向半轴超过 3 m。仅将 `max_radius` 从 1.5 改成 3，并不等价于 FIRI 的扩张范围。

Hermite 核心新增 `Options::local_range` 和 `local_progress`。每段样条按种子弧长对应到局部盒；盒子边界落在样条区间内部时，用精确 de Casteljau 细分，再施加六个方向的连续支持约束。约束作用于整个扫掠截面，不是生成后裁剪，也不是只检查离散点。BVH 查询同时受局部盒限制，避免放大数值上界后退化成逐段扫描整张地图。

本轮基准同时解除原来的 **1.5 m 半轴上限和 1.5 m 中心偏移上限**，使两者由局部盒及障碍限制。优化器保留由局部盒最大对角线导出的冗余有限上界：半轴为 `diagonal/2+0.001`，偏移为 `diagonal+0.001`。盒内椭圆直径不可能超过盒子对角线，因此这些上界不会先于盒约束限制可行截面。本轮实体模型的数值半轴上界为 5.54–5.64 m。

这是“共同局部盒 + 放开两个原上限”的联合实验，不是只改变半轴上限的单因素消融。现有 API 默认值保持兼容；基准通过 `--policy matched-box --range 3` 启用上述设置。

## 实体障碍结果

输入为同一原始占据体素中心、同一种子折线和世界边界。体素边长 0.25 m，以外接球覆盖；机器人半径 0.2 m、安全距离 0.05 m、额外认证余量 0.002 m。FIRI 原生只支持点障碍，表中的 FIRI 是 **原算法生成 + 同安全距离收缩 + shortCut**，适配方法与[上一轮报告](FIRI同输入对照.md)一致。

## 计量、验证与内存

- 每组预热一次，交替执行两种生成器，取三次生成耗时的中位数。核心库与基准程序均为 Release `-O3`，同一 Ryzen 7 9700X。文件读取、路径搜索、显示、独立审计和体积估计不计入生成耗时。
- Hermite 可复用 BVH 的建索引时间另计，本轮为 27.2–35.4 ms；一次冷启动需要再加上该成本。FIRI 包装器的全点云筛选计入 FIRI 生成时间。
- 每组使用 8 次数字移位 Sobol，每次 65,536 点，共 524,288 点。逐点流式计算并集，重叠只计一次。Hermite 归属检查考虑截面平面方程的全部根；本轮未出现未决根。误差半宽不是形式化体积界。
- 六组输出均通过生成器连续证书。附加 1,001 个截面的完整椭圆支持检查未发现局部盒越界。FIRI 均非空、端点被包含、相邻保留区域有体积重叠；三组实体结果通过球体分离及地图边界审计。
- 新增单元用例覆盖超过 1.5 m 的扩张、盒子切换落在样条内部、完整截面位于对应盒内、C² 与导数、无效范围参数；核心及体积解析回归均通过。
- 新范围六次基准进程 RSS 峰值 **27.1–35.3 MiB**。运行器强制单进程顺序执行，虚拟内存上限 **512 MiB**、CPU 软/硬限额 25/30 s、墙钟超时 40 s；超时终止整个子进程组。网格数与候选关联数仍在分配前受限。
- 构建也使用 `-j1` 和 2 GiB 虚拟内存限制。RViz 接入程序在该限制下需要更积极的 GCC 垃圾回收及 `-O1`；这不影响已完成对比所用的 `-O3` 核心库和基准程序。

## 结果说明与复现

原 1.5 m 上限确实明显压缩了可用体积；本次没有消除全部差距。Hermite 仍输出椭圆截面及 C² 连续扫掠，首末截面中心固定在种子端点；FIRI 输出可覆盖角落和端部外空间的凸多面体。共同扩张盒没有让两种表示拥有相同的可行集合。当前优化器也没有全局最大体积保证，因此不能把剩余差距全部归于 Bézier 凸包保守性。

放宽范围后，约束生成和优化都增加了开销。本轮仍是两轮膨胀、原有节点间距，没有针对体积或速度另外调参。这组结果支持继续定位约束与求解耗时，但不支持宣称当前 Hermite 已经比 FIRI 更快或更充分地利用自由空间。

```bash
python3 gcopter/tools/run_firi_comparison.py \
  --input .scratch/interactive/rviz/run_1793605002598226995_3712673/request_1 \
  --input .scratch/interactive/perlin_final/run_1793605176741410828_3715435/request_10 \
  --input .scratch/interactive/maze_connected/run_1793605479006343675_3719882/request_10 \
  --output .scratch/firi_matched_range_replay \
  --policy matched-box --range 3 --repeats 3 --samples 65536
```

原配置对照使用另一个输出目录，并改为 `--policy legacy --model solid`。运行器每次等待上一个进程结束才启动下一组。
